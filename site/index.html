One terminal for all your coding agents.
A coordinator you talk to, threads that do the work.

You talk to one coordinator. It splits the work into tasks and hands each to a thread: an agent in its own git worktree that opens a pull request and reports back. tm, a single binary, keeps every agent running in a background server when you close the terminal, and its dashboard shows what each one is doing and what waits for you. All progress lives in plain markdown under ~/.terminatr/projects/, so clearing an agent's context loses nothing.

01 What it does

  • ◆ One coordinator, many threads

    The coordinator is your single point of contact. It turns what you ask into tasks and starts a thread for each: an agent in its own git worktree and branch, so they never trip over each other. All progress lives in markdown under ~/.terminatr/projects/, so clearing an agent's context loses nothing.

  • ● Survives the terminal

    tm is a client; the agents live in a background server. Close the window, drop the SSH link, quit: they keep working. Run tm again from any terminal, at any size, and you are back. After a crash or an upgrade the server resumes them.

  • ▦ Dashboard, sidebar, popup

    Every session and project with its live state: working, blocked, idle. A project tree on the left of every screen, an info panel beside each agent, and a project popup (a) with its overview, inbox, tasks and settings. Keyboard first, mouse everywhere, the same view in every terminal you open.

  • ⎇ PRs, merged when CI is green

    Threads push their branch and open a pull request on GitHub or Azure DevOps. tm watches the checks: a failing run goes back to the thread with the log, a conflict with main asks for a merge. Threads can't merge; the coordinator does, once the checks pass.

  • ✓ Tasks and an inbox

    Tasks with steps in a plain TASKS.md: on deck, in motion, needs you, done. Threads hand in reports; the coordinator reads them from its inbox and moves the task. What waits for you, a review, a question, a red build, comes first under NEEDS YOU.

  • ⌁ Works over SSH

    It is a terminal program, so it goes where SSH goes. Copying from a pane lands on the clipboard of the machine you sit at (OSC 52). On a Mac the server starts in the desktop's session, so agents keep the keychain when you started it remotely. Remote Control picks up the coordinator from your phone.

  • ⇣ Homebrew, signed, self-updating

    One Go binary. macOS builds are signed with a Developer ID and notarised. Install from the Homebrew tap; tm update upgrades it and tm doctor checks the setup.

  • ◈ Built on Claude Code mods

    tm loads its own mod (Claude Code's plugin hooks, early access, Claude Code 2.1.289 or newer) to set and read state: whether a session is working or blocked, its context use, open questions and approvals, and the guard. No screen-scraping; a few screen rules only cross-check.

  • ⚙ Agents as data

    Claude Code and Codex today; pi and opencode will follow. Agents plug in through a TOML manifest that says how to launch and resume them and read their state, so adding one is data, not a rewrite.

03 Install

macOS 13+ or Linux (glibc 2.28+), with Homebrew and Claude Code or Codex. Newer Homebrew wants you to trust a tap's formula once.

  1. tap it
    brew tap theclifmeister/terminatr https://github.com/theclifmeister/terminatr
  2. trust it
    brew trust theclifmeister/terminatr
  3. install it
    brew install terminatr
  4. run it
    tm

Then press n for a new project and enter to start its coordinator. Ctrl+B d brings you back to the dashboard, ? lists every key. No Homebrew? The README has a one-line install from the releases. Running Codex? Using Codex covers the setup.
